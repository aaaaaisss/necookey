# 次の精度向上アイデア（2026-10-31, Hark）

前提：目標は「日常で困らない変換」。主な悩みは区切りミスとツギハギ。同音はリランカー待ち。辞書作り直しは11月にメンバー担当。

## 1. 自分専用リランカーのオンライン学習（本命）
- リランカーの特徴量重みを端末上で毎回の確定から更新（構造化パーセプトロン／ランキングSVMの1ステップ）。
- 正解＝ユーザーが確定した表記（チップで直した文は特に強い教師）。不正解＝その時の1位。
- 学習辞書が「単語を覚える」のに対し、これは「この人は かな寄り／漢字寄り、こういう区切りを好む」という癖そのものを覚える。未見の文にも効く。
- CandidateReranker の差し替え口にそのまま載る。重みは数KB。暴走防止に基準重みへの減衰＋上限。

## 2. LLMで作った日常会話コーパスでラティスLMを口語に寄せる
- システム n-gram / lattice_lm は Wikipedia 寄り→LINE的な口語で区切りが壊れやすい。
- PC 上で LLM に口語文（方言・ら抜き・〜てる・顔文字前後など）を数十万文生成→読み付け→lattice_lm を追加学習（APKサイズは据え置きで重み更新だけ）。
- 同じ生成文で「難しい評価セット」も自動で作れる（今のセットは易しすぎる問題も解決）。

## 3. 入力欄の前文脈キャッシュLM
- getTextBeforeCursor（数百字）と直近の確定履歴に出た単語を一時的にブースト。
- 会話中に一度出た固有名詞・話題語は次も同じ表記に。ユーザー辞書なしで地名・人名の再出に強くなる。
- アプリ（packageName）× 入力種別ごとに学習を分ける（チャットと検索で好みが違う）。

## 4. 「消して打ち直した」を負の教師に
- 確定直後に削除→同じ読みで別表記を確定、を検出したら、元の表記を減点、新表記を加点。
- 今は無視（選ばれなかった）しか減点材料がない。明確な「間違い」信号を拾える。

## 5. 区切り修正の一般化
- チップで切った／くっつけた位置を「読みの文字bigram境界」の事前分布として学習。
- 同じ文でなくても、同じ文字の並び（例：〜って｜る）で同じ区切りを優先。

## 6. かな書き判定器
- 口語コーパス（2）から「普通かなで書く語」（こと/とき/できる/やっぱ等）の確率を推定し、漢字化の境界コストに反映。ツギハギの予防にもなる。

ユーザー判断(10/31)：1・4・5・6 は採用候補、2・3 は不採用。
優先度：4・5（今すぐ可）→1（リランカー到着後）→6（データ源を別途検討）。
