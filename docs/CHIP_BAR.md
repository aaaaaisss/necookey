# 文節チップ UI（候補欄作り直し）設計メモ

UI なしのモデルだけ（`converter/candidatebar/ChipBar.kt`）。View・IMEService への組み込みはまだ。

## 見た目と操作（合意済み）
- 上段 = 文節チップ列（入力中ずっと。変換ボタンを押さなくても出る）。
- 下段 = 普段は予測（チップ形）。チップをタップした時だけそのチップの候補
  （漢字候補 → かな（ひらがな・カタカナ）→ 区切り候補）。もう一度タップか確定で予測に戻る。
- チップの右フリック = 1 字伸ばす、左フリック = 1 字縮める。動くのは右隣だけ
  （隣は空になれば消え、末尾チップを縮めると新しいチップができる）。フリックしたチップが選択状態になる。
- 長いチップ（読み 7 字以上）と、2・3 位の経路がそのチップの両端で区切らないチップ（区切りが揺れている）は、
  1 位経路の語分割を「自立語の頭」（漢字・カタカナ・英数で始まる語）でまとめ直して割る。
  例: 値落ち|し|て|も|歌 → `値落ちしても|歌`、胃炎|買っ|た → `胃炎|買った`。間違った変換ほど長い塊になる問題への対策。
- 区切り候補 = 読み全体の N-best のうち、選択チップの範囲で区切りが違う経路。経路の語境界が両端に来るまで
  隣のチップへ広げ（最大 3 チップ）、その経路の文節で置き換える（例: `では|着物` → `で|履物`）。
  区切りが同じで表記だけ違うものは漢字候補の役目なので出さない。

## モデル
- `ChipConverter`（読み → `ChipConversion`: 経路 = 出力・語分割・文節区切り）を注入。実機では
  getCandidatesWithoutPredictionWithBunsetsu の結果を `ChipConversion.fromEngine` で包む。`MemoChipConverter` で同じ読みは 1 回。
- `ChipBarState`（読み、チップ列、選択、読み全体の変換）は不変。`ChipBarModel` の
  `initial / lowerRow / tap / flickLeft / flickRight / pickCandidate / pickSplitAlternative / pickFullAlternative / commit`
  が新しい状態を返す（変化なしは null）。
- フリックの再変換は隣接 2 チップだけ。`ChipConverter.convert(reading, ChipContext)` に左文脈（左側チップの表記＋読み）を渡す。
  フリックで消えたチップは `ChipBarState.remembered`（範囲→チップ）に残し、区切りを戻したら再変換せず元の表記に戻す。
- `ChipBarConfig.advanceAfterPick`: 候補を選んだら次のチップへ選択を進める（既定オフ = 仕様どおり）。

## 評価
`ChipUiEvalTest`（NK_CHIP_OUT）と `tools/eval_border/chip_eval.py` → `tools/eval_border/CHIP_UI_EVAL.md`。
探索は `ChipUiSolvers.kt`（テスト側）。
結果（2026-10-28、誤り 54 文）: 全体候補ありで平均 新 1.19 手 vs 現行 1.28 手、全体候補なしで 1.96 vs 2.20
（区切り誤り 1.55 vs 2.09、ツギハギ 3.00 vs 3.67、同音 1.92 vs 2.00）。

## 次に直すとよい点（評価から）
- 予測行（チップ未選択）にいちばん怪しいチップの候補を数個混ぜる（同音を 1 手に。現行の「最初の文節の別候補」相当）。
- 揺れチップの割り方を N-best の境界の和集合にする（自立語の頭だけだと `変える仕事` のような塊が出る）。
- 区切り候補から、読み全体を 1 語で覆う文字種変換（半角カナなど）の経路を外す。
- フリック後の単独再変換は文脈なしなので、左右の確定済みチップを文脈に渡すか、全体経路の該当部分を優先する。

## 改修（2026-10-28、評価の指摘への対応）
- 予測行: チップ未選択時、いちばん怪しいチップ（2・3 位経路で区切りが揺れる 3 点/表記が揺れる 2 点/割った・伸縮した 1 点、
  同点は左）の候補を最大 3 個 `Predictions.chipPicks` で返す（UI は予測行の先頭付近）。候補 = 2・3 位のその範囲の表記 →
  チップ単独変換。候補が無いチップは飛ばす。`pickChipPick` でそのチップだけ置換（選択はしない）。
- 長い/揺れるチップの分割: 2・3 位経路の文節区切り（splitPatternByCandidateString 由来、1 位の語頭に当たるもの）を優先。
  片の読みが `minSplitPiece`（2）未満になる割り方はしない（`では`→`で|は` を避ける）。無ければ従来の自立語の頭。
- 文全体を 1 語にした漢字なしの経路（半角カナ・カタカナ等の文字種変換）は、区切り候補・揺れ判定・分割・怪しさ判定から外す
  （予測行の読み全体の別候補には残す）。
- 評価（ChipUiEvalTest）は未再実行。`NewUiSolver` は予測行のチップ候補を 1 手として数えるよう更新済み。
