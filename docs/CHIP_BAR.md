# 文節チップ UI（候補欄作り直し）設計メモ

モデルは `converter/candidatebar/ChipBar.kt`。View・IMEService への組み込みは下の「組み込み」（2026-10-28）。

## 見た目
- 上段 = 文節チップ列（入力中ずっと。変換ボタンを押さなくても出る）。
- 下段 = 普段は予測（チップ形）。チップを選択した時だけそのチップの候補（漢字候補 → かな（ひらがな・カタカナ））。
  もう一度タップか確定で予測に戻る。予測行にチップの候補は混ぜない（先読み予測が隠れるため）。
- 「怪しい」チップの下線などの強調はしない。
- 初期チップ = 1 位経路の文節。読み 7 字以上の文節だけ、1 位経路の語分割を自立語の頭（漢字・カタカナ・英数で始まる語）で
  まとめ直して割る（例: 値落ち|し|て|も|歌 → `値落ちしても|歌`）。N-best 2・3 位の区切りや表記の揺れは使わない。

## 境界操作（2026-10-28 作り直し）
実際に直したい区切りのずれは「助詞の付き先が 1〜2 字違う」が大半で（評価の区切り誤り: `ここでは|着物` → `ここで|履物`、
`駅前|運んでる` → `駅前は|混んでる`）、たまに「長い塊を離れた位置で切りたい」「切れすぎを戻したい」がある。それぞれに 1 操作ずつ当てる。

| 操作 | ジェスチャ | 手数 | モデル |
|---|---|---|---|
| 切る | チップ長押しでそのチップがかな 1 文字ずつに展開 → 文字の間をタップ（2026-10-29 に長押しで即切るへ変更、下） | 2（距離によらない） | `longPress` → `cutPositions` → `cutAt` |
| くっつける | 隣り合うチップの間をタップ（またはチップからチップへスワイプ） | 1 | `join(i)`（i と i+1） |
| ずらす | チップ端の左右フリック（右 = 1 字伸ばす、左 = 1 字縮める。動くのは右隣だけ） | 1 / 字 | `flickRight` / `flickLeft` |

- 切る: 展開中は漢字表記の代わりに読みが見えるので、誤変換で読みが分からなくなったチップでもどこで切るか選べる。
  チップの端（＝既存の境界）は切れない。1 字のチップは展開しない。展開中に別のチップをタップすると閉じる。
- くっつける: チップ間の隙間は小さいので、View では隙間のヒット領域をチップの端まで広げるか、スワイプでも受ける（モデルは同じ `join`）。
  くっつけた結果が長くても自動では割らない（ユーザーが意図して作った塊なので）。
- ずらす: 1〜2 字のずれ用に残す。末尾チップを左フリックすると新しいチップができ、右隣が空になれば消える。
- 3 操作とも、変わったチップが選択状態になり下段にその候補が出る（続けて候補を選べば 1 手）。切ったときは左の片を選択。
- 再変換は変わった範囲だけ。`ChipConverter.convert(reading, ChipContext)` に左文脈（左側チップの表記＋読み）を渡す。
  切ったときの右の片は、切ったばかりの左の片まで含めた文脈で変換する。
- 消えたチップは `ChipBarState.remembered`（範囲 → チップ）に残し、同じ範囲に戻ったら再変換せず元の表記に戻す
  （くっつけて切り直す・フリックで戻す、どちらでも元通り）。全体候補を選んだら捨てる。

### 採用しなかったもの
- 区切り候補（N-best の別経路の区切り）: 2・3 位経路に頼る部分をやめる方針と、「切る／くっつける」の結果と重なるので削除。
- 予測行の怪しいチップ候補（chipPicks）・揺れ判定による分割: 先読み予測が隠れる／N-best に頼るため削除。
- 長押し → 指を滑らせて離した位置で切る（1 ジェスチャ）: 手数は 1 になるが、展開した文字の上を指で隠しながら位置合わせするのが難しく、
  誤操作の取り消し（くっつける）も要る。モデルは `longPress` + `cutAt` で同じなので、View 側で後から足せる。

## モデル
- `ChipConverter`（読み → `ChipConversion`: 経路 = 出力・語分割・文節区切り）を注入。実機では
  getCandidatesWithoutPredictionWithBunsetsu の結果を `ChipConversion.fromEngine` で包む。`MemoChipConverter` で同じ読みは 1 回。
- `ChipBarState`（読み、チップ列、選択、展開中のチップ、読み全体の変換、remembered）は不変。`ChipBarModel` の
  `initial / lowerRow / tap / longPress / cutPositions / cutAt / join / flickLeft / flickRight / pickCandidate / pickFullAlternative`
  が新しい状態を返す（できない操作は null）。
- 入力欄への反映（純粋関数）: `composing(state)` = `ComposingView(text, selectedStart, selectedEnd)`
  （チップ表記の連結と、選択チップの UTF-16 範囲 = 色付け span。選択なしは -1）、`commit(state)` = 確定時の commit 文字列。
- `ChipBarConfig.advanceAfterPick`: 候補を選んだら次のチップへ選択を進める（既定オフ）。

## 組み込み（2026-10-28）
設定「文節チップ方式」（`necookey_chip_candidate_bar_preference`、既定オン、「2段の候補バー」が前提）でオン/オフ。
オフで従来の2段表示（TwoRowCandidateBarPlanner / publishNecookeyTwoRowBar そのまま）。既存の設定キーは変えていない。

### 構成
- **流れは2段バーのまま**: `setCandidatesNecookeyTwoRow` が予測・変換・リランカー（SUMIRE-LM）を回して `publishNecookeyTwoRowBar` で
  公開する。チップ方式はこの公開に乗るだけ（`updateChipBarForPublish`）。上段の候補 RecyclerView にはこれまでどおり2段バーの上段を
  入れておき（チップがまだ無いときのスペース変換のフォールバックが使う）、その上に `ChipStripView` を重ねて下を透明にする（alpha 0）。
- **表示データ**（純粋関数、`ChipBarPresenter.kt`）: `strip(state)` = チップの表記・選択・展開中ならかな 1 文字ずつ、
  `lowerRow(state, row, predictions)` = 下段（予測の先頭 3 個の後ろに読み全体の別候補を差し込む／チップ選択中はそのチップの漢字候補 → かな）、
  `cutOffset` = 展開中の文字の間 → 読みのオフセット、`isTouched / isEdited`、`learningFragments`（チップ = 文節）、
  `wholeConversion`（上段の 1 位＝学習・リランカー差し替え後から読み全体の `ChipConversion` を作る。split pattern が無い 1 位は語分割の自立語の頭で区切る）。
  チップ候補・全体候補は type 60 / 61 の `Candidate` にして既存の `SuggestionAdapter`（下段 `necookey_prediction_row`）にそのまま載せる。
- **View**（`ime_service/candidatebar/ChipStripView.kt`、並べ方と当たり判定は純粋な `ChipStripLayout`）: タップ＝選択/解除、
  チップ間（隙間の中心から ±(隙間/2 + min(12dp, 隣のチップ幅/4))）のタップ＝くっつける、長押し＝展開、展開中の文字の間（一番近い所）のタップ＝切る、
  チップ上の左右フリック（20dp 以上・横優位）＝1 字ずらす。はみ出したら文字を 0.7 倍まで縮め、それでも入らなければ横にスクロールできる
  （下の「2026-10-29 チップ列のスクロール」）。
  色は既存の候補欄の色（`resolveCandidatePanelColors`: 候補の背景・文字・選択色。候補の背景が透明なテーマは文字色を薄く混ぜた色）。下段はピル形
  （候補の背景を丸く塗り、区切り線を消して 3dp 離す。従来の2段表示では元に戻す）。
- **状態**: `chipBarState`（Main で更新）。読みが変わるたびに作り直す（チップを変えていたら、変わらなかった先頭部分の編集は引き継ぐ。下の「2026-10-29 スペース・打ち足し」）。同じ読みの再公開（リランカーの結果など）は、
  触っていなければ新しい 1 位で作り直し、触った後は保つ。チップ操作は `runChipBarOp` で 1 つずつ、再変換は `Dispatchers.Default` で行い、
  終わった時に読み・状態が変わっていたら捨てる。
- **再変換**（`chipEngineConvert`）: `KanaKanjiConversionSession.queryRerankPool`（getCandidatesWithoutPredictionWithBunsetsu、表示用の逐次状態は使わない、
  学習・ユーザー辞書は表示と同じ設定）で 20 件 → `ExactInputCandidatePromotionPolicy` → リランカーがあれば左文脈（入力欄の左＋左側チップの表記、
  最大 40 字）で 1 位を差し替え（`CandidateReranker` の差し替え口はそのまま）→ `ChipConversion.fromEngine`。リランカーが無ければ左文脈は使わない。
- **入力欄**: 触る前は従来どおり（ライブ変換が 1 位を出す）。触った後は `composing(state)` を setComposingText（チップごとに下線、選択チップは変換中の色、
  ほかは変換後の色。独自配色の設定に従う）し、ライブ変換・リランカーの結果では上書きしない。
- **確定**: 確定キーで、触った後なら `commit(state)` を commitText し、チップ = 文節として `ConversionLearningSession` に記録
  （変えたチップは明示選択・候補順 1、変えていないチップは候補順 0）→ `persistCompletedLearningSession`。これで負のフィードバック
  （`LearningFeedbackPlan`: 出ていた 1 位・予測を弱める）、後続語、確定直後の後退での学習取り消し（`LearningRevert`）が通常の確定と同じに動く。
  触っていなければ従来の確定。下段の予測をタップしたときは従来の候補確定（学習も従来どおり）。
- カーソル移動・末尾あり（stringInTail）などで2段バーが使えない状態になると、チップ列も消えて従来の処理に戻る。
  スペースはチップ方式の間は旧文節変換に入らない（下の「2026-10-29 スペース・打ち足し」）。

### 実機確認リスト
1. 打っている間ずっと上段にチップ列、下段に予測（ピル形）が出る。ライト/ダーク・各スキン・独自配色で読める色か。
2. チップをタップ → 選択色になり、入力欄のその範囲が色付き、下段がそのチップの候補（漢字 → ひらがな → カタカナ）。もう一度タップで予測に戻る。
3. 下段の候補をタップ → チップと入力欄の表記が変わる（確定はしない）。確定キーで入力欄の表記どおりに確定。
4. 長押し → かな 1 文字ずつに展開（振動）。文字の間をタップで 2 つに切れ、左の片が選択される。1 字のチップは展開しない。展開中に別のチップをタップで閉じる。
5. チップの間をタップ → くっついて再変換され選択される。隙間の少し内側（チップの端）でも反応するか、小さいチップがタップで選べるか。
6. チップ上で右フリック = 1 字伸ばす、左フリック = 1 字縮める（末尾チップの左フリックで新しいチップ）。フリックとタップ・長押しの誤認識が無いか。
7. くっつける → 切り直す／フリックで戻す で元の表記に戻る（remembered）。
8. 予測の先頭 3 個の後ろの「読み全体の別候補」をタップ → チップ列がその経路に置き換わる。
9. 触らずに確定・ライブ変換オフでの確定・予測タップでの確定が従来どおり。
10. チップを直して確定 → 次に同じ読みで直した表記と区切りが出る（学習。docs/LEARNING.md「チップ候補欄の学習」）。確定直後に後退 → 学習が取り消される（次に元の 1 位に戻る）。
11. 長い文でチップがはみ出すとき、文字が縮み、選択・展開中のチップが見える位置に寄るか（スクロールの確認は 20〜23）。
12. 再変換の待ち（長い読みの切る・くっつける）で引っかかりが無いか。チップ操作中に打鍵したとき古い結果で上書きされないか。
13. 設定「文節チップ方式」をオフで従来の2段表示に戻る（下段の見た目も元どおり）。横画面・タブレットのレイアウト。

## 2026-10-29 操作の追加・変更（確定ボタン・長押しで即切る・区切りドラッグ）
| 操作 | ジェスチャ | 手数 | モデル / View |
|---|---|---|---|
| 確定 | チップ列の右端の小さい確定ボタン（丸にチェック。2026-10-30 に左端から右端へ移動） | 1 | `Listener.onConfirm` → `confirmChipBar` → `commitChipBar(requireTouched = false)`（下の「確定ボタンは見えている表記で確定」） |
| 切る | チップを長押し → 押した文字の位置で即座に切る | 1 | `onLongPressCut(index, offset)` → `ChipBarModel.cutChip`（= 展開して `cutAt`） |
| 境界を動かす | 区切り（チップ間）に指を置いて左右に滑らせる → 1 字ずつ吸い付き、離したところで確定 | 1 | `onBoundaryDrag(index, delta)` → `ChipBarModel.shiftBoundary` |
| ずらす（残す） | チップ上の左右フリックで 1 字 | 1 / 字 | 従来どおり（区切りドラッグのフォールバック） |

- 確定ボタン: 候補をタップしただけだと確定キーを押すまで確定されず、そのまま打ち足すとひらがなに戻っていた。
  **確定ボタンは見えている表記で確定（2026-10-29 夜に変更）**: 押したときのチップ列の表示（`composing(state)` = `commit(state)`）を、
  チップに触っていなくてもそのまま確定する（以前は確定キーと同じで、触っていなければ従来の確定 = ライブ変換オフだとかなのまま）。
  学習は確定キーと同じ `commitChipBar` → `recordChipBarLearning`（触っていなければ明示選択なし・学習辞書には書かない、
  負のフィードバック・後続語・確定直後の後退での取り消しは同じ）。この読みのチップ状態が無いときだけ確定キーと同じ処理。
  確定キー自体は従来どおり（触った後だけチップの表記）。先に出したチップ操作（候補の差し替え・再変換）が
  終わってから確定する（`chipBarOpMutex` に並ぶ）。ボタンはスクロールせず右端に固定、チップ列はその左に並べる（2026-10-30 に左端から移動。区切りドラッグの自動スクロールの右端もボタンの左まで）。
- 長押しで切る位置: 表記の文字の境目（指に一番近いところ）を読みの位置に割り当てる（`ChipStripLayout.cutOffsetForLabel`）。
  表記が読みと同じ長さ（かなのまま等）ならそのまま、漢字なら表記の中の割合で比例配分（ずれたら区切りドラッグで直す）。両端は 1 字残す。
  1 字のチップは切れない。展開（かな 1 文字ずつ）は View からは使わなくなった（モデルの `longPress / cutPositions / cutAt` は残す）。
- 区切りドラッグ: 区切りの当たり判定（くっつけると同じ、隙間＋両側のチップ端）で押して横に touch slop 以上動かすとドラッグ。
  字の幅（「あ」の幅）ごとに 1 字動き、変わるたびに軽い振動。左右のチップとも 1 字は残す（`clampDelta`）。動かしている間は
  指の位置に境界前後のかな（各 3 字、`boundaryPreview`）を 1.3 倍で出すバブルを上段の中に描く（フルの Magnifier は使わない）。
  離したら 1 回だけ再変換（`shiftBoundary` → `moveBoundary`、変わった両チップを左文脈付きで）。動かさずに離せば従来どおりくっつける。
- `ChipStripItem.reading`（チップの読み）を足した（長押しの位置とバブル用）。

実機確認（追加）:
14. 確定ボタンで、候補を選んだ表記のまま確定される（打ち足してもひらがなに戻らない）。触っていないときもチップ列に見えている表記で確定される（ライブ変換オフでも）。
15. 長押しで押した位置の近くで切れるか（漢字のチップは比例配分なのでずれることがある）。1 字のチップで何も起きないか。
16. 区切りを左右に滑らせて 1 字ずつ動くか、バブルが指の位置に出て読めるか、フリック・タップ（くっつける）と誤認識しないか。

## 2026-10-29 スペース・打ち足し（既知の制約 2 つを解消）
- **スペース**: チップ方式がオンのとき（2段バーが使える・日本語モード）、スペースは旧文節変換（`handleJapaneseModeSpaceKeyWithBunsetsu`）に入らず、
  選択なし → 先頭のチップを選ぶ、選択中 → 次のチップへ、末尾の次は先頭へ戻る（`ChipBarModel.spaceNext`、展開は閉じる）。
  選んだチップの候補が下段に出るので、スペースで進めて候補をタップ → 確定キー（または確定ボタン）。
  入り口は `handleSpaceKeyClick`（フリック・QWERTY・物理キーボード共通）と `handleSpaceKeyClickInCustomRomaji`（今の読みのチップがあるときだけ）。
  打った直後でこの読みのチップがまだ無いときは最大 600ms 待ち（`CHIP_SPACE_WAIT_MS`）、間に合わなければ従来のスペース変換にする。
  フリックでの前候補（`cycleFocusedBunsetsuCandidate(-1)`、変換中だけ）は従来どおり。スペース長押しは下の「入力中のスペース長押し」。
  チップ方式がオフ、末尾あり・変換中などで2段バーが使えないときも従来どおり。
- **打ち足し・後退**: 読みが変わったとき、前の読みでチップを変えていたら（境界操作・候補選択・全体候補で 1 位と違う表記）、
  前後の読みの共通の先頭部分に収まる一番右の変えたチップまでを、その左のチップごと残す（`ChipBarModel.carryOver`）。
  残りは新しい読みの 1 位経路のチップ（境界が合わなければ 1 位経路の語の頭で割る）。どちらも合わないとき（残す範囲の終わりが
  新しい 1 位経路の語の途中）だけ、残りを左のチップを文脈にして裏で再変換する（それまでは新しい 1 位のまま、ライブ変換が一瞬出る）。
  最後の字が変わる打ち方（フリックの濁点・トグル）はその字を含むチップの編集は残さない（読みが共通でないので）。
  引き継いだ状態は「触った後」と同じ扱い（入力欄はチップの表記、確定キーで学習付き確定、選択はなし・下段は予測）。
  引き継ぐ前の状態は `chipBarCarryFrom` に持ち、引き継げた・確定した・チップ方式が外れたら捨てる。

実機確認（追加）:
17. 打っている途中でスペース → 先頭のチップが選択されて下段にその候補、もう一度で次のチップ、末尾の次は先頭へ。旧文節変換（チップ列が消える）にならない。
18. チップの候補を選んでから続けて打つ → 選んだ表記・区切りがそのまま残り、打ち足した部分だけ変わる。後退でも、消した字より前の編集は残る。
19. 濁点・小書き・トグルで最後の字を変えたとき、その字のチップが新しい変換になる（古い表記が残らない）。

## 2026-10-29 チップ列のスクロール（手動スクロール不可の制約を解消）
長い文でチップがはみ出すと、右端（打っている所）に寄せるだけで手ではスクロールできず、区切りドラッグ・フリックとも取り合いになって
見えないチップは編集できなかった。ジェスチャごとに役を分けて、3 つを組み合わせた。

| 指の動き | 動作 |
|---|---|
| 区切り（チップ間）の上から横に動かす | 区切りドラッグ（従来どおり）。指が表示域の端から 32dp 以内に入ると自動でスクロール（端に近いほど速く、最大 600dp/秒）し、そのまま見えていなかった所まで境界を動かせる。字数は始めた位置からの指の移動＋自動スクロール分で数える |
| チップの上から短く速く横に払う（56dp 未満かつ 220ms 以内に離す） | フリック = 1 字ずらす（従来どおり） |
| チップの上から長く（56dp 以上）またはゆっくり（220ms 超）横に動かす | 手でスクロール（切り替えた瞬間の位置から指に付いて動く。離すと慣性） |
| チップの無い所（左右の余白）から横に動かす | すぐスクロール |
| 慣性スクロール中に触る | 止まるだけ（タップ・長押しにはしない） |

- はみ出していない（スクロールできない）ときは、チップ上の横の動きは長さ・速さによらず従来どおりフリック。長押し（切る）はタッチスロップ以上動いたら取り消し（従来どおり）。
- 自動で寄せる: 選択・展開中のチップ（またはその表記）が変わったら、そのチップが見えるまで最小限スクロール（タップ・スペースで次のチップ・
  候補選択・切る/くっつける/ずらすの結果のチップ）。表示幅より広いチップは左端を優先。読みが変わったら（打ち足し・後退）手の位置を忘れて右端へ。
  それ以外の更新（再公開・リランカー・同じ選択のまま）では手でスクロールした位置を保つ。
- 純粋な部分は `ChipStripLayout`（`scrollFor(reveal, followEnd)` / `revealScroll` / `maxScroll` / `chipSwipeIsScroll` / `edgeAutoScrollSpeed`、`ChipStripLayoutTest`）。
  View は `ChipStripView`（OverScroller + VelocityTracker で慣性、区切りドラッグの自動スクロールは postOnAnimation）。
- 採用しなかったもの: チップ上の横スワイプを全部スクロールにする（フリックが消える）／スクロールバー・矢印ボタン（上段の高さが足りず、狙って押す手間が増える）。

実機確認（追加）:
20. 長い文でチップの上をゆっくり、または長く横に動かすとスクロールし、離すと慣性で流れる。チップの無い余白からでもスクロールできる。
21. はみ出しているときも、チップ上の短いフリックで 1 字ずれる（スクロールに化けない）。はみ出していないときはフリックの感覚が従来どおり。
22. 区切りを端までドラッグすると自動でスクロールし、見えていなかった位置まで動かせる。離すと 1 回だけ再変換。
23. スクロールで左の方を見ているときに、再変換や予測の更新で右端へ跳ね戻らない。打ち足すと右端へ戻る。タップ・スペースで選んだチップが見える位置に来る。

## 2026-10-29 入力中のスペース長押し = 見えている表記で確定してカーソル移動
未入力のときのスペース長押し（カーソル移動モード）を入力中にも使えるようにした。入力中にスペースを長押しすると、
いま入力欄に見えている変換をそのまま確定し、未入力のときと同じカーソル移動モードに入る（`commitComposingForSpaceCursorMove`）。
- チップ方式でこの読みのチップ状態があれば、チップ列の表示（`composing(state)`）を確定ボタンと同じ `commitChipBar(requireTouched = false)` で確定
  （学習・負のフィードバックも同じ経路）。旧文節変換中・変換中・チップ状態が無いときは確定キーと同じ処理（その時の表示を確定）。
- 入り口: カスタム配列の `KeyAction.Space` の長押し（タップ・フリックの両方の listener）とテンキーのサイドキー（`handleSpaceLongAction`）。
  変換キー（`KeyAction.Convert`）の長押しは変えていない。
- 置き換えた旧挙動: 入力中のスペース長押しは、文節変換中なら区切りパターン切り替え（`switchBunsetsuSplitPattern`）、それ以外は
  「変換キーでカーソル移動」設定がオンのときだけカーソル移動（オフなら何もしない／テンキーのサイドキーはカタカナ⇄ひらがな切り替え）だった。
  スペース長押しからはこれらを外した（区切りパターン切り替え・カタカナ切り替えは変換キーの長押し側に残る）。

実機確認（追加）:
24. 入力中にスペース長押し → 見えている表記（チップを直した後ならその表記、触っていなければチップ列の表記）で確定され、そのままカーソル移動モード。指を離すと抜ける。
25. 未入力のスペース長押し・変換キーの長押しは従来どおり。

### 未対応・既知の制約
- チップからチップへのスワイプでくっつけるのは未実装（タップのみ）。
- チップ上の横の動きはフリックとスクロールを長さ・速さで分けているので、ゆっくりしたフリック（220ms 超）はスクロールになる（はみ出していないときは従来どおりフリック）。
- 端のフェードなど「まだ続きがある」ことを示す表示は無い。
- スペースでの「次の候補」（同じチップの候補を順に回す）は無い。スペースはチップの選択を進めるだけで、候補は下段をタップ。
- 引き継ぎで裏の再変換が要るときは、終わるまで新しい 1 位（ライブ変換）が一瞬見える。
