# 文節チップ UI（候補欄作り直し）設計メモ

モデルは `converter/candidatebar/ChipBar.kt`。View・IMEService への組み込みは下の「組み込み」（2026-10-28）。
区切りの操作は「2026-11-05 長押しの区切りポップアップ」（長押し → 指を置いたまま滑らせる → 離す）とチップの間のタップ（くっつける）、
2026-11-07 から選択チップの下段の「区切りを変える候補」と端のハンドル（下の「2026-11-07 区切りを変える候補・端のハンドル」）。
候補欄はキーボードから切り離した画面幅の浮いた帯（下の「2026-10-30 浮いた候補帯」）。

## 見た目
- 上段 = 文節チップ列（入力中ずっと。変換ボタンを押さなくても出る）。
- 下段 = 普段は予測（チップ形）。チップを選択した時だけそのチップの候補（漢字候補 → かな（ひらがな・カタカナ））。
  もう一度タップか確定で予測に戻る。予測行にチップの候補は混ぜない（先読み予測が隠れるため）。
- 「怪しい」チップの下線などの強調はしない。
- 初期チップ = 1 位経路の文節。読み 7 字以上の文節だけ、1 位経路の語分割を自立語の頭（漢字・カタカナ・英数で始まる語）で
  まとめ直して割る（例: 値落ち|し|て|も|歌 → `値落ちしても|歌`）。N-best 2・3 位の区切りや表記の揺れは使わない。

## 2026-11-07 区切りを変える候補・端のハンドル（区切りの直しを少ない手数で・見つけやすく）

- 狙い: 区切りの直しは「チップを選ぶ → 下段から選ぶ」の 2 手で済むようにする（A）。思った候補が無ければ、選んだチップの端の
  ハンドルを横に動かして区切りをずらす（B）。どちらも選んだチップのまわりに出るので、長押しを知らなくても見つかる。
- 長押しのポップアップ（11/05）は**残す**: ハンドルは今ある区切りを動かす・くっつけるだけで、長いチップの好きな所に新しく区切りを
  入れるのは長押しだけ（割る候補は N-best に出たときだけ）。チップの間のタップ（くっつける）も残す。

| 指の動き | 動作 | 実装 |
|---|---|---|
| チップをタップ | 選択（従来どおり）。下段 = 今の表記・1 番目の別候補の後ろに**区切りを変える候補**（最大 3、印付き）→（直前に区切りを変えていれば）「↶戻す」→ 文全体の経路での同じ範囲の表記（最大 2）→ 残りの候補・かな | `ChipBarModel.lowerRow` / `refineLowerRow`、`ChipBarPresenter.lowerRow` |
| 下段の区切りを変える候補をタップ | その区切り・表記にする（変換し直さない。作ったチップは RESIZED = 明示選択として学習・`LearnedBoundaries` に記録）。選択は元のチップの頭を含むチップ | `ChipBarModel.applyAlternative` → `applySegmentation(…, surfaces)` |
| 下段の「↶戻す」 | 直前の区切りの変更（候補・ハンドル・長押し・間のタップ・戻す以外）の前の状態に戻す。次の操作をするまでだけ出る | IMEService `chipBarUndo` |
| 選択チップの端のハンドル（左右の隣があれば、チップの端から下へ短い軸と丸いつまみ）を横に動かす | その区切りを**相対的に** 1 字ずつずらす（指 26dp ≒ 1 字、CLOCK_TICK、長押しと同じポップアップに読み・カーソル・「離すとずらす」）。隣のチップの端まで動かすと「離すとつなぐ」（くっつく） | `ChipStripLayout.handleAt / handleDrag`、`HandleDrag`、`HoldCursor(minGap, maxGap)` |
| 離す | 区切りを動かして再変換（`onSegmentation`、選択はそのチップのまま。左のハンドルでくっつけたらくっついたチップ） | `HandleDrag.finish` |
| ハンドルを押したまま上へポップアップの外 / 下へ 48dp 以上 | 「やめる」（長押しと同じ） | `updateHold` |
| ハンドルの所を押すだけ（動かさない） | 普段のタップ（間ならくっつける、チップの上なら選択/解除） | 当たり判定は区切り（隙間の真ん中）±22dp（`HANDLE_TOUCH_DP` 44dp） |

- **区切りを変える候補の作り方**（`ChipBarModel`、どれも選択チップと左右の隣までの範囲だけ。区切りも表記も今と違うものだけ、重複は除く）:
  1. 文全体の N-best 経路（`state.whole.paths`、候補欄の更新で既に取ってあるもの。追加の変換なし）を文節の塊にし（split pattern、
     無ければ自立語の頭で）、選択チップから始めて経路の境目と今のチップの境目が両方そろう所まで広げた範囲を置き換える（`alternativeFrom`）。
  2. 選択チップだけの変換（チップ候補のために既にしている）の経路の文節（割る候補）。
  3. 下段を出した**後に裏で**（選択の反応を待たせない）: 選択チップを左隣・右隣とくっつけた読みを左文脈付きで変換（1 選択につき最大 2 回、
     メモ化）し、その経路の文節どおり → 1 つにくっつけた塊、の順に 1 つずつ（`refineLowerRow`）。
     同じ変換の 1 位で選択チップと同じ範囲になった語の表記（例: ほうほう|ないか → ない|か の「ないか」）は普通の候補として前に寄せる（`context`）。
  - 例: いい|方法|内科 の「内科」→「←方法ないか」と候補「ないか」、は|磨いて の「磨いて」→「←歯磨いて」、では|着物 の「着物」→「←で｜履物」。
- **印**: 候補の前後に小さく（0.6 倍）向き（← 左隣を取り込む / → 右隣 / ←…→ 両方 / なし = 割る）、塊の間に「｜」。「戻す」は「↶」。
  type 62〜65（向き）・66（戻す）、`Candidate.score` = 候補の番号（`ChipBarPresenter.segmentFor` は番号と表示を照合し、ずれていたら表示で探す）。
- 純粋な部分のテスト: `ChipBarTest`（segmentAlternatives… / refine… / alternativeFrom… / applySegmentationWithSurfaces…）、
  `ChipBarPresenterTest.lowerRowOrdersSegmentsUndoAndContext`、`ChipStripLayoutTest`（handles… / handleDrag… / holdCursorRespectsHandleRange）。
- 提案からの変更: ハンドルは区切りを「隣の端を越えて」ではなく「隣の端まで」でくっつく（越える先は無いので）。両方向とも隣の端まで動かせば
  くっつく（左のハンドルを右のチップの終わりまで動かしても同じ）。区切りを変える候補の「割る」は追加の変換をしない（N-best とチップの変換に
  出たものだけ）。ライブプレビューはチップ列の中ではなく長押しと同じ上のポップアップ（チップの幅が変わって指の下がずれないように）。

実機確認（2026-11-07）:
51. チップをタップ → 下段の 3 番目あたりに「←方法ないか」のような印付きの候補が出て、少し遅れて（くっつけた変換の分）増えることがある。
    選択の反応（色が変わる・下段が変わる）が以前より遅くなっていないか。長い読み・リランカーありで引っかからないか。
52. 区切りを変える候補をタップ → 入力欄・チップ列がその区切り・表記になり、元のチップの所が選択される。確定 → 次に同じ読みで同じ区切り（学習）。
53. 印（← → ｜ ↶）が小さく読めて邪魔でないか、各スキン・独自配色で見えるか。候補の読み（ルビ）表示の設定で崩れないか。
54. 選択チップの端にハンドルが見えるか（ライト/ダーク・スキン）。左端・右端のチップでは片側だけ。
55. ハンドルを横に動かす → ポップアップに読みとカーソル、1 字ごとに振動、「離すとずらす」。隣の端まで動かすと「離すとつなぐ」。離すとその区切りで再変換、選択はそのまま。
56. ハンドルの所をタップ（動かさない）→ 従来どおり くっつける / 選択。チップ列がはみ出しているとき、選択チップの端以外からのスクロールが従来どおり（端の ±22dp からはスクロールでなくハンドル）。
57. ハンドルを動かして上へ外す / 下へ 48dp 外す → やめる（何も変えない）。
58. 区切りを変えた直後に下段の「↶戻す」→ 前の区切り・表記・選択に戻る。候補を選ぶ・ほかのチップを選ぶと「戻す」が消える。
59. 長押しのポップアップ（11/05）・チップの間のタップ・スペースでの選択送りが従来どおり。

## 2026-11-05 長押しの区切りポップアップ（区切り編集モードを置き換え）

- 実機の声: 区切り編集モード（長押し → 文字の間をタップ → 完了）でもまだ手数が多い。**押したまま 1 回で終わる**形にした。
  区切り編集モード（かなのマス表示・「完了」ボタン・もう一度長押しで取り消し）は**削除**（ジェスチャを少なく保つ）。

| 指の動き | 動作 | 実装 |
|---|---|---|
| チップをタップ | 選択 / 解除（従来どおり） | `onChipTap` |
| チップの間をタップ | くっつけて再変換（11/04 復活のまま） | `ChipStripLayout.joinAt` → `onJoin` |
| チップを長押し | チップ列の**上**にポップアップ（PopupWindow、タッチを取らない）: 読み全体のかなを大きく（チップの文字の 1.35 倍）同じ幅（30dp）のマスに。今の区切りは太い棒、区切りでない境目は薄い短い線。押した所に一番近い文字の境目にカーソル（太い棒＋上の三角）。カーソルの境目が指の真上に来る位置に出す（画面の端では寄せる）。右上に離したときの動作（離すと区切る / 離すとつなぐ / やめる） | `startHold`、`ChipStripLayout.holdStartGap`（押した割合をチップの読みの字数に当てる）、`HoldPopupRenderer` |
| 押したまま横に滑らせる | カーソルが**相対的に**動く: 指の移動 26dp ごとに 1 境目（スペースキーのカーソル移動と同じ）。ポップアップの文字は動かない・絶対位置のずれが溜まらない・磁石なし。1 つ動くごとに軽い振動（CLOCK_TICK）。端で止まったらそこで基準を取り直す（戻すとすぐ動く） | `ChipStripLayout.HoldCursor` |
| 離す | カーソルの境目に区切りを入れる（区切りの上なら消す = つなぐ）→ その場で再変換（`onSegmentation` → `ChipBarModel.applySegmentation`、変わった一番左のチップが選択） | `finishHold` |
| 指を上へポップアップの外まで / 下へ 48dp 以上外す | 「やめる」表示（文字を薄く、カーソルを消す）。そのまま離すと何も変えない。戻せば続く | `updateHold` |
| 長い読み（画面幅に入らない） | 入る分だけの窓。カーソルが窓の端の境目を越えたときだけ 1 字ずらす（端に「…」） | `ChipStripLayout.holdWindowFirst / holdInitialFirst` |
| 打鍵で読みが変わる・チップ列が消える・スペース | ポップアップを閉じる（何も変えない） | `setData` / `onVisibilityAggregated` / `handleChipBarSpace` → `cancelHold` |

- ポップアップが出せないとき（ウィンドウトークンが無い等）は、チップ列の上に重ねて同じ絵を描く。
- 削除: `ChipStripView` の区切り編集モード（`enterSegmentEdit / exitSegmentEdit / cancelSegmentEdit / toggleGap / drawSegmentEdit / drawDone`、「完了」）、
  `ChipStripLayout.segCellLeft / segWidth / segGapAt / segEntryScroll`。残す: `segSource / segOffsets / toggleBoundary / codePoints`、モデルの `applySegmentation`。
- テスト: `ChipStripLayoutTest`（holdStartGap・HoldCursor・holdWindowFirst）。
- 実機確認: (1) チップを長押し → 上にかなが大きく出て、押した所の近くにカーソル (2) 押したまま左右に動かすと 1 字ずつ動き、
  文字は動かない・振動 (3) 離すとそこで切れて再変換、区切りの上で離すとつながる (4) 上へ外す / 下へ外すと「やめる」になり、離しても変わらない
  (5) 長い読みで窓がずれる (6) タップで選択・間のタップでくっつけるは従来どおり (7) ポップアップが入力欄に重なって邪魔にならないか。
- 歩幅 `HOLD_STEP_DP`（26dp）・マス `HOLD_CELL_DP`（30dp）・やめる範囲 `HOLD_CANCEL_BELOW_DP`（48dp）は ChipStripView の定数。

## 2026-11-04 くっつける（チップの間のタップ）を普段のモードに復活

- 実機の声: 区切り編集モードだけだと、2 つをつなぐのにも 長押し → 区切りタップ → 完了 の 3 手かかる。普段のモードで
  **2 つのチップの間を 1 回タップ = くっつけて再変換・そのチップを選択**（モデル `ChipBarModel.join` は残っていたのでそれを使う）。軽い振動。
- 当たり判定 `ChipStripLayout.joinAt`: 隙間全体＋両側のチップの端（それぞれ min(6dp, チップ幅の 1/5)）。チップ中央側の 3/5 以上は
  タップ＝選択のまま（旧版は ±min(12dp, 幅/4) で端の選択タップを取っていた）。隙間は 6dp → 10dp に広げて見た目でも狙いやすく。
  タップは joinAt を先に見て、外れたら chipAt。
- 長押しの区切り編集モード（切る・消す）はそのまま。くっつけすぎた塊は編集モードで切り直す。→ 2026-11-05 に長押しの区切りポップアップへ置き換え。
- テスト: ChipStripLayoutTest.joinAtCoversGapAndThinChipEdgesOnly。
- 実機確認: (1) 間のタップでつながって選択されるか (2) 小さい 1 字チップがタップで選べるか（端を押して誤ってくっつかないか）
  (3) スクロール中・慣性停止のタップでくっつかないか。

## 2026-11-02 区切り編集モード（境界操作をこれ 1 つに作り直し）— **2026-11-05 に削除**（上の「長押しの区切りポップアップ」に置き換え。`applySegmentation` は残る）
実機で「区切りをどう動かす・足すのか分からない」「長押しで切る位置が押した所からずれる（かなに展開すると文字が動く＋語の境目への磁石）」
「直感的でない」。操作を一番単純な形にした。**区切りの操作はこれだけ**（下の 10-28〜10-30 の境界操作のジェスチャはすべて削除）。

| 指の動き | 動作 | モデル / View |
|---|---|---|
| チップをタップ | 選択 / 解除（下段にそのチップの候補）。従来どおり | `onChipTap` → `ChipBarModel.tap` |
| チップ列のどこかを長押し | **区切り編集モード**に入る: 読み全体をかな 1 文字ずつ、同じ幅（34dp）のマスに並べ、今の区切りを太い縦線（選択色）で出す。区切りで分けた塊ごとに角丸の背景。区切りでない文字の間には薄い短い線（タップできる所の目印） | View だけ（`ChipStripView.enterSegmentEdit`） |
| 文字の間をタップ（一番近い境目。磁石・吸い付きなし） | そこの区切りを入れる（無ければ）／消す（あれば）。軽い振動。**その都度モデルに反映**（再変換は裏で。入力欄の表記もその都度変わる）。マスの幅は区切りによらず固定、線は幅を取らないので文字は動かない | `onSegmentation(reading, boundaries, null)` → `ChipBarModel.applySegmentation` |
| 右端の「完了」（確定ボタンの場所） | 編集モードを抜ける（区切りはもう反映済み）。変わった一番左のチップが選択されていて下段にその候補 | View だけ |
| 打鍵で読みが変わる・確定・チップ列が消える・スペース | 編集モードを抜ける（区切りはもう反映済み。打ち足し・後退は従来の引き継ぎ `carryOver` で残る） | `setData`（読みが変わった）/ `onVisibilityAggregated` / `handleChipBarSpace` → `exitSegmentEdit` |
| 編集モード中にもう一度長押し | 取り消し: 入ったときの区切り（と選択）に戻して抜ける | `onSegmentation(reading, 入ったときの区切り, 入ったときの選択)` |
| 横に動かす | スクロール（普段も編集モードも。離すと慣性） | View |

- **`ChipBarModel.applySegmentation(state, boundaries, select = null)`**（純粋関数、`ChipBarTest`）: 区切りをまとめて指定する。
  前と同じ範囲のチップはそのまま（再変換しない）。新しい範囲は remembered にあればその表記に戻し（区切りを入れて消せば元どおり、選んだ表記も戻る）、
  無ければ左から順に、左側のチップ（作ったばかりの片を含む）を左文脈にして 1 チップとして再変換（`Origin.RESIZED`。ユーザーが作った塊なので自動では割らない）。
  両端・範囲外・サロゲートペアの途中は無視。区切りが今と同じなら null。選択は既定で変わった一番左のチップ。
- 「確定するまで反映しない」ではなく**タップごとに反映**にした: 抜け方（完了・打鍵・確定キー・確定ボタン・スペース長押し・カーソル移動…）が何であっても、
  その時のチップ状態が既にユーザーの区切りなので、キーごとのフックや確定経路の変更が要らない。続けて速くタップしたときは
  IMEService が最後の区切り（`chipBarSegmentTarget`）だけを反映する（並んだ古い操作は同じ区切りになるので何もしない）。
- 学習: 確定は従来どおり `commitChipBar` → `recordChipBarLearning`（作ったチップは RESIZED = 明示選択、`LearnedBoundaries` は 1 位の区切りとの差を記録）。
- 編集モードは View だけの表示状態（モデルの `expanded` は使わない）。区切りの表示はユーザーのタップのまま（モデルの結果を待たない）。
  同じ読みの再公開（モデルの反映・リランカー・予測）では続け、読みが変わったら抜ける。
- 入ったとき、押したチップの先頭の文字のマスが、そのチップの左端があった画面位置に来るようにスクロールする（`segEntryScroll`）。
- 純粋な部分は `ChipStripLayout`（`segSource / segOffsets / segCellLeft / segWidth / segGapAt / toggleBoundary / segEntryScroll`、`ChipStripLayoutTest`）。

**削除した View の操作**（モデル関数はテスト・評価 `ChipUiSolvers` が使うので残す: `longPress / cutPositions / cutAt / expandForCut / collapse / cutChip / join / flickLeft / flickRight / shiftBoundary`）:
チップ間タップでくっつける（`Hit.Join`）、チップ上のフリックで 1 字ずらす、区切りドラッグ（とバブル・端の自動スクロール）、
長押しの切るカーソル（展開・磁石 `snapCutGap` / `SNAP_BONUS_CHARS`・PopupWindow のバブル・`cutPreview`）、展開中の文字の間タップで切る（`Hit.Cut`）、
フリックとスクロールの切り分け（`chipSwipeIsScroll`。横の動きは常にスクロール）。`ChipStripItem.wordBoundaries` と `ChipBarPresenter.wordBoundaries`（磁石用）も削除。

実機確認（2026-11-02、これを優先。下の 4〜7・15・16・21・22・26〜31 は削除した操作なので不要）:

## 境界操作（2026-10-28 作り直し）— **2026-11-02 に View から削除**（上の「区切り編集モード」に置き換え。モデル関数は残す）
実際に直したい区切りのずれは「助詞の付き先が 1〜2 字違う」が大半で（評価の区切り誤り: `ここでは|着物` → `ここで|履物`、
`駅前|運んでる` → `駅前は|混んでる`）、たまに「長い塊を離れた位置で切りたい」「切れすぎを戻したい」がある。それぞれに 1 操作ずつ当てる。

| 操作 | ジェスチャ | 手数 | モデル |
|---|---|---|---|
| 切る | チップ長押しでそのチップがかな 1 文字ずつに展開 → 文字の間をタップ（2026-10-29 に長押しで即切るへ変更、下） | 2（距離によらない） | `longPress` → `cutPositions` → `cutAt` |
| くっつける | 隣り合うチップの間をタップ（またはチップからチップへスワイプ） | 1 | `join(i)`（i と i+1） |
| ずらす | チップ端の左右フリック（右 = 1 字伸ばす、左 = 1 字縮める。動くのは右隣だけ） | 1 / 字 | `flickRight` / `flickLeft` |

- 切る: 展開中は漢字表記の代わりに読みが見えるので、誤変換で読みが分からなくなったチップでもどこで切るか選べる。
  チップの端（＝既存の境界）は切れない。1 字のチップは展開しない。展開中に別のチップをタップすると閉じる。
- くっつける: チップ間の隙間は小さいので、View では隙間のヒット領域をチップの端まで広げるか、スワイプでも受ける（モデルは同じ `join`）。
  くっつけた結果が長くても自動では割らない（ユーザーが意図して作った塊なので）。
- ずらす: 1〜2 字のずれ用に残す。末尾チップを左フリックすると新しいチップができ、右隣が空になれば消える。
- 3 操作とも、変わったチップが選択状態になり下段にその候補が出る（続けて候補を選べば 1 手）。切ったときは左の片を選択。
- 再変換は変わった範囲だけ。`ChipConverter.convert(reading, ChipContext)` に左文脈（左側チップの表記＋読み）を渡す。
  切ったときの右の片は、切ったばかりの左の片まで含めた文脈で変換する。
- 消えたチップは `ChipBarState.remembered`（範囲 → チップ）に残し、同じ範囲に戻ったら再変換せず元の表記に戻す
  （くっつけて切り直す・フリックで戻す、どちらでも元通り）。全体候補を選んだら捨てる。

### 採用しなかったもの
- 区切り候補（N-best の別経路の区切り）: 2・3 位経路に頼る部分をやめる方針と、「切る／くっつける」の結果と重なるので削除。
- 予測行の怪しいチップ候補（chipPicks）・揺れ判定による分割: 先読み予測が隠れる／N-best に頼るため削除。

  誤操作の取り消し（くっつける）も要る。モデルは `longPress` + `cutAt` で同じなので、View 側で後から足せる。

## 2026-10-29 チップ列のスクロール（手動スクロール不可の制約を解消）— 2026-11-02: フリックと区切りドラッグが無くなったので、横の動きは常にスクロール（自動スクロールも削除）
長い文でチップがはみ出すと、右端（打っている所）に寄せるだけで手ではスクロールできず、区切りドラッグ・フリックとも取り合いになって
見えないチップは編集できなかった。ジェスチャごとに役を分けて、3 つを組み合わせた。

| 指の動き | 動作 |
|---|---|
| 区切り（チップ間）の上から横に動かす | 区切りドラッグ（従来どおり）。指が表示域の端から 32dp 以内に入ると自動でスクロール（端に近いほど速く、最大 600dp/秒）し、そのまま見えていなかった所まで境界を動かせる。字数は始めた位置からの指の移動＋自動スクロール分で数える |
| チップの上から短く速く横に払う（56dp 未満かつ 220ms 以内に離す） | フリック = 1 字ずらす（従来どおり） |

| 慣性スクロール中に触る | 止まるだけ（タップ・長押しにはしない） |

- はみ出していない（スクロールできない）ときは、チップ上の横の動きは長さ・速さによらず従来どおりフリック。長押し（切る）はタッチスロップ以上動いたら取り消し（従来どおり）。

- 採用しなかったもの: チップ上の横スワイプを全部スクロールにする（フリックが消える）／スクロールバー・矢印ボタン（上段の高さが足りず、狙って押す手間が増える）。

### 未対応・既知の制約
- 区切り編集モードは、読みを変えないキー（キーボードの切り替え・カーソルキー以外の記号面など）では抜けない（「完了」で抜ける）。戻るキーでの取り消しは無い（もう一度長押し）。

- 引き継ぎで裏の再変換が要るときは、終わるまで新しい 1 位（ライブ変換）が一瞬見える。
