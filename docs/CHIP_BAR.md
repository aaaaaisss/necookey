# 文節チップ UI（候補欄作り直し）設計メモ

UI なしのモデルだけ（`converter/candidatebar/ChipBar.kt`）。View・IMEService への組み込みはまだ。

## 見た目
- 上段 = 文節チップ列（入力中ずっと。変換ボタンを押さなくても出る）。
- 下段 = 普段は予測（チップ形）。チップを選択した時だけそのチップの候補（漢字候補 → かな（ひらがな・カタカナ））。
  もう一度タップか確定で予測に戻る。予測行にチップの候補は混ぜない（先読み予測が隠れるため）。
- 「怪しい」チップの下線などの強調はしない。
- 初期チップ = 1 位経路の文節。読み 7 字以上の文節だけ、1 位経路の語分割を自立語の頭（漢字・カタカナ・英数で始まる語）で
  まとめ直して割る（例: 値落ち|し|て|も|歌 → `値落ちしても|歌`）。N-best 2・3 位の区切りや表記の揺れは使わない。

## 境界操作（2026-10-28 作り直し）
実際に直したい区切りのずれは「助詞の付き先が 1〜2 字違う」が大半で（評価の区切り誤り: `ここでは|着物` → `ここで|履物`、
`駅前|運んでる` → `駅前は|混んでる`）、たまに「長い塊を離れた位置で切りたい」「切れすぎを戻したい」がある。それぞれに 1 操作ずつ当てる。

| 操作 | ジェスチャ | 手数 | モデル |
|---|---|---|---|
| 切る | チップ長押しでそのチップがかな 1 文字ずつに展開 → 文字の間をタップ | 2（距離によらない） | `longPress` → `cutPositions` → `cutAt` |
| くっつける | 隣り合うチップの間をタップ（またはチップからチップへスワイプ） | 1 | `join(i)`（i と i+1） |
| ずらす | チップ端の左右フリック（右 = 1 字伸ばす、左 = 1 字縮める。動くのは右隣だけ） | 1 / 字 | `flickRight` / `flickLeft` |

- 切る: 展開中は漢字表記の代わりに読みが見えるので、誤変換で読みが分からなくなったチップでもどこで切るか選べる。
  チップの端（＝既存の境界）は切れない。1 字のチップは展開しない。展開中に別のチップをタップすると閉じる。
- くっつける: チップ間の隙間は小さいので、View では隙間のヒット領域をチップの端まで広げるか、スワイプでも受ける（モデルは同じ `join`）。
  くっつけた結果が長くても自動では割らない（ユーザーが意図して作った塊なので）。
- ずらす: 1〜2 字のずれ用に残す。末尾チップを左フリックすると新しいチップができ、右隣が空になれば消える。
- 3 操作とも、変わったチップが選択状態になり下段にその候補が出る（続けて候補を選べば 1 手）。切ったときは左の片を選択。
- 再変換は変わった範囲だけ。`ChipConverter.convert(reading, ChipContext)` に左文脈（左側チップの表記＋読み）を渡す。
  切ったときの右の片は、切ったばかりの左の片まで含めた文脈で変換する。
- 消えたチップは `ChipBarState.remembered`（範囲 → チップ）に残し、同じ範囲に戻ったら再変換せず元の表記に戻す
  （くっつけて切り直す・フリックで戻す、どちらでも元通り）。全体候補を選んだら捨てる。

### 採用しなかったもの
- 区切り候補（N-best の別経路の区切り）: 2・3 位経路に頼る部分をやめる方針と、「切る／くっつける」の結果と重なるので削除。
- 予測行の怪しいチップ候補（chipPicks）・揺れ判定による分割: 先読み予測が隠れる／N-best に頼るため削除。
- 長押し → 指を滑らせて離した位置で切る（1 ジェスチャ）: 手数は 1 になるが、展開した文字の上を指で隠しながら位置合わせするのが難しく、
  誤操作の取り消し（くっつける）も要る。モデルは `longPress` + `cutAt` で同じなので、View 側で後から足せる。

## モデル
- `ChipConverter`（読み → `ChipConversion`: 経路 = 出力・語分割・文節区切り）を注入。実機では
  getCandidatesWithoutPredictionWithBunsetsu の結果を `ChipConversion.fromEngine` で包む。`MemoChipConverter` で同じ読みは 1 回。
- `ChipBarState`（読み、チップ列、選択、展開中のチップ、読み全体の変換、remembered）は不変。`ChipBarModel` の
  `initial / lowerRow / tap / longPress / cutPositions / cutAt / join / flickLeft / flickRight / pickCandidate / pickFullAlternative`
  が新しい状態を返す（できない操作は null）。
- 入力欄への反映（純粋関数）: `composing(state)` = `ComposingView(text, selectedStart, selectedEnd)`
  （チップ表記の連結と、選択チップの UTF-16 範囲 = 色付け span。選択なしは -1）、`commit(state)` = 確定時の commit 文字列。
- `ChipBarConfig.advanceAfterPick`: 候補を選んだら次のチップへ選択を進める（既定オフ）。

## 評価
`ChipUiEvalTest`（NK_CHIP_OUT）と `tools/eval_border/chip_eval.py` → `tools/eval_border/CHIP_UI_EVAL.md`。
探索は `ChipUiSolvers.kt`（テスト側、`NewUiSolver` = 上の手数で数える）。
結果（2026-10-28、誤り 54 文）: 全体候補ありで平均 新 1.17 手 vs 現行 1.28 手、全体候補なしで 1.93 vs 2.20
（区切り誤り 1.36 vs 2.09、ツギハギ 3.00 vs 3.67、同音 1.92 vs 2.00）。最短手順で使われた境界操作はフリック 19・くっつける 11・切る 0
（評価セットに「長い塊を離れた位置で切る」誤りが無い）。詳細と問題点は CHIP_UI_EVAL.md。
